# 収穫ノートのテンプレート

以下の構成で出力する。**該当が無いセクションは見出しごと省く**（空のセクションを残さない）。

```markdown
---
captured: 2026-07-06
source: harvest
project: obsidian-tech
tags: [claude-code, skill]
---

# セッションの主題を一言で

## やったこと

何に取り組み、どこまで進んだか。成果物（作成・変更したファイル、動いた機能）を具体的に。

## 設計判断とその理由

「AとBで迷ってAにした。理由は〜」の形で。採らなかった選択肢と捨てた理由こそ価値があるので必ず残す。

## ハマり → 解決

- **症状**: 何が起きたか（エラーメッセージは原文で）
- **原因**: 突き止めた根本原因
- **解決**: 何をしたら直ったか

複数あれば繰り返す。未解決のまま回避したものは正直に「回避」と書く。

## 未解決・申し送り

次のセッション（または他の人）が最初に見るべきこと。やり残し、既知の不具合、次の一手。

## 記事ネタになりそうな点

このセッションの中で、他者に共有する価値がありそうな学び・話題を1〜3行で。無ければセクションごと省く。
```

## 記入の指針

- frontmatter の `source: harvest` は固定（後続の取り込みツールがセッション由来と識別するため）。`project` はリポジトリ名
- 「やったこと」は箇条書きでよいが、「設計判断」「ハマり→解決」は文章で書く。理由や経緯こそが後から読む価値の中心
- コード・コマンド・エラーは原文のままコードブロックで残す（要約すると再現できなくなる）
