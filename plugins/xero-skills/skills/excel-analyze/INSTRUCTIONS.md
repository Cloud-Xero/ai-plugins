# excel-analyze

複雑なExcelブックをWebアプリ（ダッシュボード等）へ移植するための解析パイプライン。4つの専用エージェントを順に起動し、機械可読データ（JSON）と人間向けドキュメント（Markdown）を段階的に積み上げる。

## パイプライン全体像

| 工程 | エージェント | 入力 | 出力 |
|---|---|---|---|
| 1. 構造棚卸し | `excel-inventory` | .xlsx | `01_inventory.json` / `01_inventory.md` |
| 2. 依存グラフ | `excel-dep-graph` | 01_inventory.json | `02_dependencies.json` / `02_dependency-graph.md` |
| 3. ロジック仕様 | `excel-logic-spec` | 01, 02 の JSON | `03_logic-spec.md` |
| 4. スナップショット | `excel-snapshot` | 02_dependencies.json | `04_snapshot.json` / `04_test-cases.md` |

工程間には依存関係があるため**必ず直列に実行**する（並列化しない）。ただし工程3と工程4は互いに独立（どちらも工程2の出力のみに依存）なので、この2つだけは並列起動してよい。

## 手順

### 0. 準備

1. 対象 Excel ファイルのパスを特定する。引数で渡されていなければユーザーに尋ねる。相対パスは絶対パスに解決し、ファイルの存在を確認する
2. 出力ディレクトリを決める: `<カレントディレクトリ>/excel_analysis/<ブック名（拡張子なし）>/`
3. 既に同名の出力ディレクトリがあり成果物が存在する場合は、上書きしてよいかユーザーに確認する（途中から再開したい場合は、存在しない成果物の工程だけを実行する）

### 1〜4. エージェントの起動

各工程を Agent ツールで起動する。`subagent_type` にエージェント名を指定し、プロンプトには必ず以下を含める:

- 対象 Excel ファイルの**絶対パス**
- 出力ディレクトリの**絶対パス**
- （工程3のみ）ユーザーがこのExcelについて教えてくれた背景情報（業務ドメイン、何のブックか）があれば添える。ラベル推定の精度が上がる

実行順:

1. `excel-inventory` を起動 → 完了報告を確認
2. `excel-dep-graph` を起動 → 完了報告を確認
3. `excel-logic-spec` と `excel-snapshot` を**同一メッセージで並列起動** → 両方の完了を確認

各工程の完了時には、エージェントの報告（件数・警告）を1〜2行でユーザーに中間報告する。エージェントが失敗した場合は、失敗内容をユーザーに伝えてから対処する（同じ呼び出しを黙って繰り返さない）。

### 5. 最終報告

全工程完了後、ユーザーに以下をまとめて報告する:

- 成果物6ファイルの一覧（パス付き）
- ブックの全体像（シート数、数式数、入力/出力セル数）
- **要確認事項**（03_logic-spec.md の不明点リスト、動的参照・外部参照・循環参照・ERROR値などの警告）を必ず転記する
- 次のステップの提案（要確認事項の解消 → Webアプリの計算層実装 → 04_snapshot.json での回帰テスト）

## 注意

- 解析のみを行う。**元のExcelファイルは絶対に変更しない**
- Webアプリの実装まではこのスキルのスコープ外。求められたら解析完了後に別タスクとして進める
- .xls（旧形式）の場合は openpyxl で読めないため、先に .xlsx への変換をユーザーに依頼する
