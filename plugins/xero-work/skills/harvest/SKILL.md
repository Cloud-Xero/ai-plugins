# セッション収穫スキル

いま進行中のセッション（会話）を振り返り、後から素材として使える形の収穫ノートを1ファイル残す。
記事ネタ・引き継ぎ・自分用の作業記録、用途はプロジェクト次第。**このスキル自体は抽出と保存だけを行い、後続処理には踏み込まない。**

## 手順

### 1. 出力先の解決

出力先は環境変数 `HARVEST_OUTPUT_DIR` のみを見る（`~/.claude/settings.json` の `env` で設定される）。

- 設定されていれば、そのディレクトリに保存する（ディレクトリが無ければ作成し、その旨を報告に含める）
- **未設定なら収穫を行わず停止し**、`~/.claude/settings.json` の `env` に `HARVEST_OUTPUT_DIR` を設定するようユーザーに促す。設定例:

  ```json
  { "env": { "HARVEST_OUTPUT_DIR": "/path/to/harvest" } }
  ```

  設定変更はセッション再起動後に反映される点も伝える

### 2. セッションの振り返りと抽出

現在の会話全体を振り返り、[note-template.md](./note-template.md) の観点で抽出する。

- **セッションで実際に起きたことだけを書く**。記憶があいまいな箇所は、`git log` / `git diff` / 実ファイルで裏取りしてから書く。裏取りできないものは「未確認」と明記するか省く
- ユーザーの発言・判断はユーザーの言葉のニュアンスを残して記録する（勝手に整った表現に均さない）
- 些末なやり取り（タイポ修正・単純な確認）は収穫しない。後から読む価値がある粒度に絞る
- **バージョン管理の操作そのもの（コミット・push・PR作成・マージなど）は成果として書かない**。それらは手段であって収穫対象ではない。抽出するのは「何を作ったか・どう設計したか・何にハマってどう解決したか」というコアな中身。git 操作は裏取り（`git log` / `git diff`）の手段としてのみ使う
- **ノート単体で読んで理解できる自己完結した文章にする**。この収穫ノートはブログ等の素材になる前提。「前回の続きで」「さっき直した件」のようなセッション文脈に依存した書き方はせず、対象・背景をその場で明示し、読者が前提知識なしで読めるようにする
- **固有名詞を持ち込まない**。この収穫ノートはそのまま公開記事の素材になる前提なので、社名・プロジェクト名・リポジトリ名・プロダクト名・個人名などの固有名詞は書かず、「あるリポジトリ」「サブディレクトリ構成のプロジェクト」のように一般化した表現に置き換える。技術的な学びは固有名詞を伏せても成立する。frontmatter の `project` 欄も同様に、公開して差し支えない一般名でなければ省く

### 3. 保存

- **1セッション = 1ファイル**。トピックが複数あってもファイルは分けず、セクションで区切る
- ファイル名: `yyyymmdd_{slug}.md`（slug はセッションの主題を表す短い英語）
- 同名ファイルが既にある場合は `-2` を付けて別ファイルにする（上書きしない）

### 4. 完了報告

- 保存先パス
- 収穫ハイライト（設計判断・ハマり解決を中心に2〜3行）
- テンプレの「記事ネタになりそうな点」に書いた内容があれば一言添える

## 原則

- **捏造禁止**。体験・数値・エラーメッセージをそれらしく創作しない。収穫ノートの価値は一次情報であることにある
- 秘匿情報（APIキー・顧客名・社外秘の値）はノートに書き込まない。必要なら `<秘匿>` に置換する
- 収穫はセッションの終わりに限らない。区切りごとに複数回呼ばれても、その時点までの内容で1ファイル作ってよい
