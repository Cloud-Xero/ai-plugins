# セッション引き継ぎスキル

いまのセッションを畳んで新しいセッションを立ち上げざるを得ないとき、**次のセッションが即座に作業を再開できる引き継ぎ**を作り、**ファイルに保存せずターミナルに出力する**。
出力は、新セッションの最初のメッセージにそのまま貼り付けられる粒度・形式にする。

## いつ使うか

- ツールの結果チャネルが壊れた（固定文字列が返る・空が返る・エラーが続く）
- 出力が得られず作業を続行できない
- コンテキストが飽和して動作が不安定になった
- そのほか、現在のセッションを終了して新しく立ち上げ直したいとき

## 手順

### 1. セッションの棚卸し（裏取りしてから書く）

現在の会話を振り返り、引き継ぎに必要な事実を集める。**記憶だけで書かず、一次情報で裏を取る**:

- `git status` / `git log --oneline -10` / `git diff --stat` で、実際に何がどこまで変わったかを確認する
- 触ったファイル・残作業は実ファイルやツール結果で確認する
- 裏取りできないものは書かないか、`（未確認）` と明記する

### 2. ターミナルに出力する（ファイルは書かない）

**このスキルはファイルを作らない。** 引き継ぎは 1 つのコードブロックにまとめてターミナルに出力し、ユーザーがそのままコピーできるようにする。
`$ARGUMENTS` に補足があれば、それを踏まえて内容を調整する。

### 3. 出力フォーマット

以下の見出しを、埋まる項目だけ簡潔に。長文の物語にせず箇条書き主体で、コピペ前提の 1 コードブロックにまとめる:

```
## 引き継ぎ

### ゴール
- （最終的に何を達成したいか。1〜2行）

### 現在地
- （いまどこまで進んだか。直近の状態）

### 残タスク
1. （次にやること。順序どおりに）
2. …

### 確定事項・判断
- （すでに決めたこと。新セッションで蒸し返さないため）

### 触ったファイル
- `path/to/file` — （変更内容と状態。git status ベース）

### ハマり・注意
- （既知の落とし穴。今回セッションが壊れた原因があれば必ず書く）

### 次の一手
- （新セッションが最初に実行すべきコマンド／アクション。そのまま打てる形で）
```

### 4. 出力後

- 「この内容を新しいセッションの最初のメッセージに貼ってください」と一言添える
- ユーザーが項目の追加・修正を求めたら、その場で出力し直す（ファイルは作らない）

## 原則

- **憶測禁止**。裏取りできないことを事実のように書かない。不明点は `（未確認）` と明記する
- **ファイルに保存しない**。ターミナル出力のみ。これがこのスキルの肝（作業ログをファイルに残したいときは harvest スキルを使う）
- **簡潔に**。新セッションが読んですぐ動ける最小限にする。冗長な経緯説明は削る
- 秘匿情報（APIキー・顧客名・社外秘の値）は書かない。必要なら `<秘匿>` に置換する
- バージョン管理の操作（コミット・push・PR）は「次の一手」に必要な場合だけ書く。それ自体を成果として並べない
